Your domains

    Serving it for real

    This page is the control panel. Actually answering requests for customer domains needs a server that you run. The pattern: one public IP, a reverse proxy that issues a certificate the first time a verified domain is requested, and a lookup that maps each hostname to a site.

    {
  on_demand_tls {
    ask http://localhost:9000/is-verified
  }
}

https:// {
  tls {
    on_demand
  }
  reverse_proxy localhost:3000
}

    Your app at localhost:3000 reads the Host header and returns the matching site. The /is-verified endpoint answers 200 only for domains that passed the TXT check, so nobody can request certificates for domains they don’t own.
